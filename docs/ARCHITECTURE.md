# 架构与生命周期

## 数据路径

OBS 原生推流输出 H.264/AAC 到 `127.0.0.1:19360`。兼容 HTTP-FLV 的本机转发器向伴侣网络素材提供数据；伴侣使用自己的正常编码与上传路径。RTMP 与 HTTP 监听都只绑定回环地址。

原生 OBS 插件增加一个 Tools 菜单入口并提供 `PING/STATUS/STOP_LOCAL`。停止操作核验本机服务地址和流名称，在 OBS UI 线程请求 `obs_output_stop`，不调用录制停止功能。

## 权限与进程

面板程序默认 `asInvoker`。普通启动器验证同用户、同会话和精确可执行文件路径；不存在当前版本后台时，才通过标准 Windows UAC 启动相同程序的 `--worker` 模式。

后台 IPC 拒绝远程客户端，限定用户 SID、会话、命令及报文大小，不接受文件路径、外部程序、Shell 命令或任意伴侣 RPC。所有引擎操作串行处理，面板刷新与耗时的 SDK/转发器操作分开。

## 素材管理

适配层限定已审查伴侣路径、进程启动时间和管道服务器 PID。只管理固定名称、类型、回环 URL 与完整字段吻合的源。共享素材表、顺序表及置顶表需一致，不按名称猜测身份。

伴侣重启可能重新分配 UUID。恢复要求旧 owner 生命周期已变化、旧 ID 确认不存在、只有一个完整匹配候选、getter 与登记内容一致。先归档旧记录、原子保存新身份，再修改设置；异常、多候选或不完整数据会拒绝接管。

停止不会删除素材。音量与监听设置读回只证明设置值；可见性读回也不能代替原生隐藏或解码验证。因此停止完成还要求 OBS 输出与转发器都确认关闭。

## 连接保留

本机研究中发现，一个原生客户端在伴侣仍活着时断开，可能影响其他连接。桥接停止后仍保留原生管道，直到原伴侣主进程退出。退出后台因此可能等待伴侣正常退出；不强制结束仍连接的客户端。

软件升级需要重新审查，不能把未知版本的异常当作“素材不存在”而新增、删除或放宽校验。
